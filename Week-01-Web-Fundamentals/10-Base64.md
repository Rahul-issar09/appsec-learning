# Introduction

While testing web applications, security engineers frequently encounter strings that appear random.

Example

```
SGVsbG8=
```

or

```
YWRtaW46YWRtaW4xMjM=
```

These are usually **Base64 encoded**, not encrypted.

One of the first skills of an Application Security Engineer is recognizing Base64 and decoding it.

---

# What is Base64?

Base64 is an **encoding scheme** that converts binary or text data into ASCII text.

Its purpose is to make data safe for transmission through systems that primarily support text.

Unlike encryption,

Base64 **does not provide security**.

Anyone can decode Base64 without a secret key.

---

# Why Base64 Exists

Computers store information in binary.

Example

```
010101010110...
```

Some communication protocols only support text.

Base64 converts binary into readable ASCII characters.

```
Binary

↓

Base64 Encode

↓

ASCII Text

↓

Transmit

↓

Decode

↓

Original Data
```

---

# How Base64 Works

Original Data

```
Hello
```

↓

Base64 Encode

```
SGVsbG8=
```

↓

Decode

```
Hello
```

The original information is preserved.

No information is hidden.

---

# Base64 Character Set

Base64 uses only these characters.

```
A-Z

a-z

0-9

+

/

=
```

The equals sign

```
=
```

is used as padding when necessary.

Examples

- File Uploads

---

# Base64 in HTTP

One common use is **Basic Authentication**.

Username

```
admin
```

Password

```
admin123
```

Browser combines them.

```
admin:admin123
```

Then Base64 encodes them.

```
YWRtaW46YWRtaW4xMjM=
```

HTTP Request

```http
Authorization: Basic YWRtaW46YWRtaW4xMjM=
```

The server decodes the value and validates the credentials.

---

# Base64 in JWT

A JWT has three parts.

```
Header

.

Payload

.

Signature
```

Example

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9

.

eyJ1c2VySWQiOjEwMSwicm9sZSI6InVzZXIifQ

.

signature
```

The Header and Payload are Base64URL encoded.

They are **not encrypted**.

Anyone can decode them.

Only the Signature protects the JWT from unauthorized modification.

# Base64 in Application Security

Whenever you intercept a request, ask yourself:

Does this look like Base64?

Example

```
YWRtaW46YWRtaW4=
```

↓

Decode

```
admin:admin
```

Another example

```
UmFodWw=
```

↓

Decode

```
Rahul
```

Always inspect encoded values before assuming they are encrypted.

# Base64 vs URL Encoding

| Base64 | URL Encoding |
|----------|--------------|
| Converts data into ASCII text | Makes URLs safe |
| Uses letters, numbers, +, / | Uses % followed by hexadecimal |
| Used for transporting data | Used in URLs |
| Easily reversible | Easily reversible |

Example

Base64

```
Rahul

↓

UmFodWw=
```

URL Encoding

```
Rahul Issar

↓

Rahul%20Issar
```

---

# Base64 vs Encryption

| Base64 | Encryption |
|----------|------------|
| Encoding | Security Mechanism |
| No secret key | Secret key required |
| Easily decoded | Requires decryption |
| No confidentiality | Provides confidentiality |

---

# Base64 vs Hashing

| Base64 | Hashing |
|----------|---------|
| Reversible | One-way |
| Encoding | Integrity Verification |
| Original data can be recovered | Original data cannot be recovered |

Example

Password

```
Password123
```

Base64

```
UGFzc3dvcmQxMjM=
```

↓

Decode

```
Password123
```

Hash

```
$2b$12$...
```

↓

Cannot recover original password.

---

# Common Mistakes

❌ Thinking Base64 is encryption.

It is not.

---

❌ Storing passwords using Base64.

Passwords should be hashed using algorithms such as bcrypt or Argon2.

---

❌ Assuming random-looking strings are secure.

Always try decoding them.

Base64 is an encoding scheme used to convert binary or text data into ASCII text.

---

No.

Anyone can decode Base64.

---

## Why is Base64 used?

# AppSec Checklist

Whenever I see Base64:

- Can I decode it?
- Does it contain credentials?
- Does it contain JWT data?
- Is sensitive information exposed?
- Is the application relying on Base64 for security?
- Can I modify the decoded data?

# Key Takeaways

- Base64 is an encoding mechanism.
- It does not provide security.
- Anyone can decode Base64.
- Base64 is widely used in JWTs, Basic Authentication, APIs, and file transfers.
- Application Security Engineers frequently decode Base64 while analyzing requests.
